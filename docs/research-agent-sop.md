# Reports Agent SOP / Prompt 边界

> Last verified: 2026-09-08（新日报真实11部门生成及成品复审）
> 目标：让部门 Agent 像投研部门，不像角色扮演；让 Reader 只展示结论、依据、反证和下一步。

## 运行链路

```text
Daily Universe
→ Evidence Pool
→ Department Context Pack
→ 宏观/地缘/市场/行业/自选影响并行
→ 基本面/技术/情报承接行业结论
→ Risk / RedTeam（核对多空双方）
→ CIO 主判断、研究评级、参与条件
→ 事实校验与观点保留（每部门输出）
→ ReaderV3 / Diagnostics
```

硬边界：

- Agent 不直接抓数、不读本地文件、不改持仓。
- Agent 只读分配给自己的 Context Pack。
- Agent 必须引用 evidence id；引用不存在则失败或 fallback。
- evidence id 存在仍不够：主体、指标、时间、来源等级和结论语义必须匹配。
- 搜索、新闻、Tavily、GDELT、研报观点只能作为 discovery/opinion。
- 最终默认 Reader 只读 CIO + 分部门摘要 + 证据样例。
- MacroAgent 不得用长期国债收益率与政策利率比较来判断收益率曲线；必须使用 10Y-2Y、10Y-3M 等可比国债期限。
- 历史分位等事实比较需要匹配数据；资料不足的估值/趋势判断保留为研究意见并提示局限，不由关键词替换器另写观点。
- 因果解释、未来路径和评级可以是明确主观判断，不强制改成“可能/待验证”。事实、解释、预测的身份分开；不能捏造已经发生的数字、事件或持仓结果。
- 原系统 LLM 分析、外部研报和搜索摘要都是 opinion/discovery 输入，不是 verified fact。


## 本期研究目标（2026-09-08 内容与呈现收口）

- 财报原文已解释现金流主因时，必须使用该解释；“缺量化桥接”不能写成“没有原文解释”。区分定性主因、金额拆解和主营回款质量。
- 公司推荐需要正向驱动及当前估值要求，不能只以“现金流大于利润，尚未证伪”构成买入理由。无确定催化仍可基于趋势、相对价值或盈利预期差提出清晰意见。
- 行业优先方向补充1–2项有区分度的经营、供需、价格或政策材料；确实只有价格证据时直接标清趋势策略，不给所有方向堆叠同一缺口套话。
- CIO开篇直接说明具体选择；评级与入场节奏分开。对各主要主题分别回答正向论证、关键反证、取舍、改判条件，不把所有相反情景揉成一段。下一步只突出三项最重要跟踪，不复述全部公司观点。
- 摘要以60–100字为编辑指引，完整论证保留在结构化观点；不是硬解析门。未接持仓只作简短范围说明，不编造组合或重复长假设。

- **近期变化、历史参照、建议期限分开**。默认突出近1个月变化、未来1–2个月机会，不把此前资料截掉，也不要求持有到某日。具体观点可以短至几天或长至多个季度，说明当前影响和改变判断的条件。
- `RESEARCH_RECENT_CHANGE_MONTHS` / `RESEARCH_OUTLOOK_MONTHS` 配置重点（默认1/2，整数1..60）。只影响新建DailyUniverse及其Prompt/Reader；不重写已存日报。候选线索保持原近1个日历月的新鲜度规则，不随研究期限加长而复活旧热榜。
- 历史按岗位选用：基本面使用已有最近8–12个报告期；宏观可参照2–5年周期；市场/行业/技术可比较3–6个月；新闻/地缘突出本周和本期增量，必要时追溯事件链。以上是分析指引，不是承诺已获取相应年限，更不是硬性缺口门槛。
- 原始财务历史最多保留12期；宏观Prompt保留近期8点及跨可用历史的带日期样本（最多24点），完整源历史仍在Evidence。标记实际起止/抽样范围；不能把12个观测值自动称为同比，也不能把全样本分位叫近一年分位。
- 每公司核心历史/估值后优先一份相关财务正文节选，再填财务摘要和价格，保持基本面32条事实预算。已拿到的正文解释不应被重复指标挤掉；资料尚无正文的不伪造。
- 未有确定催化，不等于不能给意见：趋势、估值、盈利预期差也可支持推荐。Risk/RedTeam/CIO按相同主体、时点、期限比较意见；短线看淡与长期看好不必互相否决。
- 自选池由用户维护；系统研究候选独立。采集器从本期已有热股/筛选/行业成分行提取明确代码，每市场最多补3个研究标的，补行情/基本面/公告后再分析。不根据LLM猜测代码扩池。
- A/H/US行业意见不局限于自选股。行业可看好/中性/看淡；个股可买入/中性/卖出。没有优势可明确回避，不能为了评级数量强行买入。
- 基本面先业务和利润驱动，再拆经营现金流（回款、营运资本、金融子公司、一过性因素），再做估值与本期机会。保留季度/累计期和历史序列，不能把现金流总额增长等同主营改善。
- 官方公告可读正文节选：每标的最多2份、每份12MB/前40页PDF上限；提取经营变动说明，保留来源、摘要范围和内容hash。失败保留标题并记录失败，不冒充已读全文。不是所有长报告均已覆盖。
- CIO明确写“现在建议 / 改变意见的条件 / 下次复核什么”；不只写“不做什么”。红队检查过度乐观也检查过度悲观，其异议不会自动取消评级。
- 完整传递所选claim的ID、直接证据、评级、周期和参与条件。Risk/RedTeam/CIO至多64条依赖证据；确实超预算且支撑不全的claim显式省略，不拿无来源摘要代替。
- 事实校验仍拒绝错数、错主体、错引用、时效错配、用20日高点冒充历史新高、仅Form4标题声称减持。取消约440行事后改写观点的字符串逻辑；不再把AI的未来触发条件私自改成另一个条件。

### 验证边界

- 摘要可以转述有据论点，不要求逐字复制正文。校验真实错误，不把否定句中的“放量”、一般语言中的“组合”当作相反断言；跨部门研究允许引用同主体财务与行情，不放行错主体/错数。完整原claim保留在Diagnostics，方便反查误删。

## 本轮输入与编辑修复

- Technical / Fundamental / Macro 的紧凑事实上限为 32；股票按市场和标的轮询分配，不把全盘资料塞给所有部门。`provider_run:` 仅进入诊断摘要，不占事实槽位。
- 财报期、同期比较期、宏观前值/趋势及数据时间依据保留到实际 Prompt；行情单点与 K 线趋势、当前估值与历史分位分开。
- 地缘优先制裁/贸易、能源、航运等有明确资产传导的问题，例行月报仅作背景。此排序不把 discovery 升级为事实，也不代表覆盖全部国际事件。
- CIO 先面向读者说主判断、优先关注什么、避免什么，再解释取舍；不以“收窄市场部门、保留风险部门”的会议记录代替结论。正反意见按同一主题比较，不要求相反或等权。
- Reader 保留原判断，静态渲染不因出现“不操作”就把其他持仓止损/减仓建议改写；报告仍不执行任何交易。

## Prompt 分层

每个 Agent 都有岗位边界。不是每个 Agent 都做人设。

| Agent | Prompt 强度 | 输入边界 |
|---|---|---|
| CIOAgent | 深度 SOP | 部门结论、红队、风险、核心 evidence、source health 摘要 |
| RedTeamAgent | 深度 SOP | 部门摘要、风险输出、核心 evidence |
| RiskAgent | 深度 SOP | 部门摘要、风险 evidence、decision signals |
| FundamentalAgent | 深度 SOP | 财务、估值、SEC/CNINFO/HKEX/SSE/SZSE、公告 |
| MacroAgent | 深度 SOP | FRED、利率、通胀、信用、流动性、能源 |
| GeoPolicyAgent | 深度 SOP | GDELT、Tavily、ReliefWeb、制裁、冲突、贸易政策 |
| MarketAgent | 轻量岗位卡 | 本轮已覆盖市场的指数、市场宽度、资金面、市场统计；不强求不存在的三地同构数据 |
| SectorAgent | 轻量岗位卡 | 行业、风格、热点、候选池 |
| TechnicalAgent | 轻量岗位卡 | K 线、趋势、量价、指标 |
| IntelAgent | 轻量岗位卡 | 公告、新闻、搜索线索、催化剂 |

## 女娲使用边界

可用：

- 离线打磨 CIO / RedTeam / Risk / Fundamental / Macro / GeoPolicy 的岗位 SOP。
- 提炼角色职责、分析框架、禁止事项、质量检查表。
- 做 prompt 质量复核。

不可用：

- 不参与运行时事实判断。
- 不生成 verified fact。
- 不替代数据源。
- 不直接写投资结论。

## 输入与输出收口

- 共享规则只保留证据等级、时点、因果、universe 和真实缺口 6 类硬约束。
- 部门 Prompt 只追加本部门的分析方法，不再重复 provider、原报告摘录和全量上下文。
- 岗位 `avoid`、部门分析规则、输出合同各自只出现一次；system prompt 只负责角色和输出入口，不再复述证据政策。
- 原系统 LLM 结论以紧凑 opinion 输入给相关部门；Risk / RedTeam / CIO 只读部门结论和关键 evidence，不重读原报告。
- 运行时要求单一 JSON object，用 backend 的 JSON mode 约束。
- Markdown 解析只作历史产物/兼容 fallback，不是新 Prompt 的双轨输出合同。

每个部门必须包含（待确认项仅在真实存在时）：

```text
结论
依据
引用 evidence id
反证
待确认项
下一步
置信度
```

置信度口径：保留模型自评用于诊断，不把一条推演或未保留草稿扩散为整个部门的中等评级。Reader 按保留结论逐条展示论据支持程度（有据支持/部分支持/研究判断/存在争议），不是预测胜率；未来触发条件不计入当前结论评级。

待确认项规则：

- 没有会改变结论的缺口，就写空数组或“无”。
- 不允许为了模板完整硬写“数据缺口”。
- 单个 provider 失败但同域已有 verified/derived evidence，只能写“待确认/需补强”，不能写“无法分析”。
- “无 / 暂无 / 无关键缺口”不会进入 Reader 的待确认项统计。
- 已确认持仓为 0 是业务状态，不是数据缺口；只有持仓快照未接入才记待确认项。
- 市场部门只比较已有市场级证据的市场。只有个股样本时明确为样本，不要求 Agent 虚构对应市场宽度。
- 当前估值可以展示；“历史低/高位”必须有本地历史分位或同业基准，至少 20 个日度样本前不输出历史分位。

CIO 的下一步必须覆盖：

```text
现在建议
改变意见的条件
下次复核什么
```

如果 CIO 未完整给出，Reader 会从 CIO 待确认项、Risk 和 RedTeam 的触发条件补齐，但不会展示工程修复术语。

## Reader 规则

ReaderV3 固定展示：

1. 今日总判断
2. 核心理由
3. 下一步
4. 报告主线：市场、宏观与地缘、行业/风格、候选、重点个股、持仓、风险、数据可信度
5. 分部门摘要
6. 证据与可信度

默认 Reader 禁止显示：

```text
ReportArtifact
sourceHealthV2
providerMatrix
RAW_AGENT
DERIVED_FROM_ARTIFACT
claimPolicy
artifactId
errorType
fallbackTo
recordCount
runMatrix
evidence_ledger
provider_runs
```

这些只进 Diagnostics。

## 正反观点裁决

RedTeam 不是把正方结论机械取反。它必须指出：替代解释、证据薄弱点、失效条件和遗漏风险。

CIO 必须输出：

1. 正反双方共同确认的事实；
2. 当前基准情景；
3. 最强替代情景；
4. 为什么暂时采用基准情景；
5. 哪些可观测触发器会推翻判断。

Reader区分事实和研究判断，不把推断统一改成条件化套话。SourceHealth高不等于预测胜率高。
